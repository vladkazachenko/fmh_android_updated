# Результаты тестирования

## 1. Результаты автоматизированного тестирования

В рамках второй части дипломного проекта было автоматизировано 26 тест-кейсов мобильного приложения «Мобильный хоспис».

Для автоматизации использовались:

* Python;
* pytest;
* Appium;
* UiAutomator2;
* Page Object Model;
* Allure.

Финальный запуск автотестов выполнен командой:

```bash
pytest -v -s --alluredir=allure-results
```

Результат финального прогона:

* всего тестов — 26;
* успешно пройдено — 24;
* завершилось с ошибкой — 2;
* время выполнения — 15 минут 44 секунды.

Неуспешно завершились:

* TC-002 — авторизация с неверным логином;
* TC-003 — авторизация с неверным паролем.

В обоих случаях автотест ожидает сообщение:

`Wrong login or password`

Фактически приложение отображает:

`Something went wrong. Try again later.`

Падение этих тестов связано с обнаруженным дефектом приложения, а не с ошибкой реализации автотестов.

По результатам тестирования дефект зарегистрирован в GitHub Issues.

## 2. Дополнительное ручное тестирование

После выполнения автоматизированных тестов дополнительно вручную была проверена функциональность Control Panel.

Проверена сортировка новостей по дате публикации. Для проверки были созданы две тестовые новости с разными Publication date. После применения сортировки порядок новостей изменялся в соответствии с датой публикации.

Результат:

**CH-031 — Пройден.**

Также вручную проверена фильтрация новостей в Control Panel:

* по статусу Active;
* по статусу Not active;
* по категории;
* по периоду публикации.

Во всех случаях в списке отображались новости, соответствующие выбранным параметрам.

Результат:

**CH-032 — Пройден.**

Дополнительно была проверена публикация активной новости. Созданная новость со статусом Active и Publication date `04.09.2026` корректно появилась в разделе News с датой публикации `04.09.2026`.

## 3. Обнаруженные дефекты

### Дефект 1. Некорректное сообщение при неверных учётных данных

При попытке авторизации с неверным логином или паролем вместо ожидаемого сообщения:

`Wrong login or password`

отображается сообщение:

`Something went wrong. Try again later.`

Дефект выявляется автоматизированными тестами TC-002 и TC-003.

### Дефект 2. Некорректное отображение даты создания новости в Control Panel

При создании новой новости Publication date отображается корректно, однако Creation date содержит некорректную дату.

Например, для новости, созданной 04.09.2026:

* Publication date — `04.09.2026`;
* Creation date — `10.02.58646`.

Аналогичное поведение наблюдалось и у других новостей.

Для дефекта была добавлена отдельная проверка:

**TC-061 / CH-101 — Отображение даты создания новости в Control Panel.**

Результат:

**CH-101 — Не пройден.**

Дефект зарегистрирован в GitHub Issues.

## 4. Сравнение ручного и автоматизированного тестирования

Точный хронометраж ручного прохождения чек-листа во время первого этапа не фиксировался.

С учётом количества проверок и необходимости вручную выполнять авторизацию, навигацию, создание, редактирование, удаление, фильтрацию и повторное открытие экранов ориентировочное время полного ручного прохождения актуального чек-листа составляет около **2 часов 30 минут**.

Это значение является оценочным, а не результатом фактического замера.

Финальный автоматизированный прогон 26 выбранных тест-кейсов занял:

**15 минут 44 секунды.**

Прямое сравнение этих значений является условным, поскольку ручной чек-лист содержит больше проверок, чем выбранный набор автоматизированных тест-кейсов.

Тем не менее автоматизация значительно сокращает время повторного выполнения выбранных регрессионных сценариев. После первоначальной разработки автотестов их можно запускать повторно без необходимости вручную выполнять одни и те же действия.

Кроме сокращения времени повторных проверок, автоматизация обеспечивает:

* одинаковую последовательность выполнения тестовых шагов;
* повторяемость проверок;
* автоматическую фиксацию результатов;
* формирование Allure-отчёта;
* автоматическое сохранение скриншота при падении теста.

Ручное тестирование при этом остаётся необходимым для исследовательских проверок, визуальной оценки интерфейса и проверки сценариев, которые не вошли в автоматизацию.

## 5. Итог

В рамках дипломного проекта выполнено ручное и автоматизированное тестирование мобильного приложения «Мобильный хоспис».

Автоматизировано 26 выбранных тест-кейсов.

Результат финального автоматизированного прогона:

* 24 теста — пройдено;
* 2 теста — не пройдено из-за обнаруженного дефекта приложения;
* время выполнения — 15 минут 44 секунды.

Дополнительное ручное тестирование подтвердило корректную работу сортировки и фильтрации в Control Panel.

В ходе тестирования обнаружены два дефекта:

1. некорректное сообщение при авторизации с неверными учётными данными;
2. некорректное отображение Creation date в Control Panel.

Результаты автоматизированного запуска сохранены в `allure-results.zip`. Для анализа результатов также сформирован Allure-отчёт.
