# План тестирования приложения «Мобильный хоспис»

## 1. Цель тестирования

Целью тестирования является проверка корректной работы мобильного приложения «Мобильный хоспис», выявление возможных дефектов и подтверждение работоспособности основных пользовательских сценариев.

В рамках дипломного проекта планируется выполнить ручное тестирование приложения, составить чек-лист и тест-кейсы, а затем автоматизировать выбранные сценарии с помощью UI-тестов.

## 2. Объект тестирования

Объектом тестирования является мобильное приложение «Мобильный хоспис», предназначенное для просмотра и управления новостями хосписа, а также просмотра тематических цитат.

## 3. Функциональность приложения

В рамках тестирования проверяются следующие функциональные возможности приложения:

* авторизация пользователя;
* сохранение пользовательской сессии после успешного входа;
* выход из учетной записи;
* просмотр списка новостей на главном экране;
* просмотр даты создания новости;
* сворачивание и разворачивание карточек новостей;
* переход между разделами Main и News;
* просмотр тематических цитат в разделе **Love is all**;
* разворачивание и сворачивание цитат;
* прокрутка списка цитат;
* сортировка списка новостей;
* фильтрация новостей по категории;
* фильтрация новостей по периоду публикации;
* создание новости;
* редактирование существующей новости;
* удаление новости;
* изменение статуса активности новости;
* сохранение и отмена изменений при создании или редактировании новости.

## 4. Границы тестирования

В рамках дипломной работы проверяются:

* корректность авторизации;
* работа основных экранов приложения;
* корректность отображения элементов пользовательского интерфейса;
* навигация между разделами приложения;
* работа со списком новостей;
* работа фильтрации и сортировки новостей;
* работа панели управления новостями (Control Panel);
* создание, редактирование, удаление и изменение статуса новостей;
* работа раздела **Love is all**;
* корректность отображения сообщений и данных.

В рамках данной работы не проверяются:

* производительность приложения;
* нагрузочное тестирование;
* безопасность приложения;
* отказоустойчивость серверной части;
* работа приложения на различных версиях Android и различных моделях устройств;
* тестирование сетевого взаимодействия и API.

## 5. Виды тестирования

В ходе выполнения дипломной работы применяются следующие виды тестирования:

* функциональное тестирование;
* UI-тестирование;
* позитивное тестирование;
* негативное тестирование;
* smoke-тестирование;
* регрессионное тестирование.

## 6. Тестовая среда

Тестирование выполняется в следующей среде:

* Android Studio;
* Android Emulator;
* эмулятор Google Pixel 4;
* Android API 36;
* тестовая учетная запись:

    * логин: `login2`;
    * пароль: `password2`.

## 7. Инструменты

Для выполнения дипломной работы используются:

* Android Studio;
* Espresso;
* JUnit4;
* Allure;
* Git;
* GitHub.

## 8. Этапы тестирования

### 8.1. Планирование

На этапе планирования определяются границы приложения, основные функциональные возможности и пользовательские сценарии.

### 8.2. Ручное тестирование

Проводится проверка основных функций приложения вручную.

Результаты фиксируются в чек-листе `Check.csv`.

При обнаружении дефектов или несоответствий они фиксируются отдельно и учитываются при подготовке тест-кейсов.

### 8.3. Подготовка тест-кейсов

На основании проведенного ручного тестирования составляются тест-кейсы для основных пользовательских сценариев.

Тест-кейсы сохраняются в файле `Cases.csv`.

Для каждого тест-кейса указывается возможность его автоматизации. Если сценарий невозможно покрыть UI-тестом, указывается причина.

### 8.4. Автоматизация

После проверки первого этапа дипломным руководителем планируется:

* настройка проекта для UI-тестирования;
* добавление необходимых зависимостей;
* создание тестового класса;
* автоматизация выбранных тест-кейсов с использованием Espresso и JUnit4;
* добавление проверок результатов выполнения каждого действия;
* подключение Allure для формирования отчета.

### 8.5. Составление отчета

После выполнения автоматизированных тестов планируется:

* сформировать Allure-отчет;
* проверить результаты выполнения тестов;
* сравнить время ручной проверки по чек-листу и автоматизированной проверки;
* подготовить итоговые материалы проекта.

## 9. Критерии начала тестирования

Тестирование начинается при выполнении следующих условий:

* проект успешно открыт в Android Studio;
* приложение успешно собирается без ошибок;
* приложение установлено на эмулятор или мобильное устройство;
* доступны тестовые учетные данные для авторизации.

## 10. Критерии завершения первого этапа

Первый этап считается завершенным после выполнения следующих условий:

* определены границы тестирования;
* определен проверяемый функционал приложения;
* проведено ручное исследовательское тестирование;
* составлен чек-лист;
* выполнены проверки из чек-листа;
* подготовлены тест-кейсы;
* для тест-кейсов определена возможность автоматизации;
* результаты ручной проверки зафиксированы в соответствующих файлах.

После проверки первого этапа дипломным руководителем выполняется переход к автоматизации UI-тестов и подготовке отчета.

## 11. Критерии завершения проекта

Дипломный проект считается завершенным после выполнения следующих условий:

* автоматизированы выбранные тест-кейсы;
* UI-тесты успешно запускаются;
* подключен Allure;
* сформирован отчет о результатах тестирования;
* подготовлен файл `README.md` с инструкцией по запуску автоматизированных тестов;
* подготовлен файл `Result.md` со сравнением времени ручной и автоматизированной проверки;
* сформирован архив `allure-results.zip`.
